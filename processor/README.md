# Российский сервер обработки аудио (Pterodactyl)

Самостоятельный Python-сервис для отдельного сервера Pterodactyl. Docker и TLS-сертификаты не нужны.

Соединение между ботами и процессором защищено PSK-протоколом: взаимная проверка владения общим секретом (HMAC-SHA256), шифрование и аутентификация каждого TCP-фрейма через AES-256-GCM, ключи сеанса выводятся через HKDF-SHA256. Сам секрет по сети не передаётся. Используй случайный секрет длиной не менее 32 байт.

## 1. Создание сервера в Pterodactyl

- Создай сервер Python 3.12 (подойдёт 3.11).
- Назначь TCP allocation, например порт 9443, и открой его во внешнем firewall.
- Загрузи содержимое папки processor/ в корень сервера. В корне должны находиться server.py, secure_transport.py и requirements.txt.
- Импортируй egg pterodactyl/egg-bw-voice-processor.json либо задай переменные вручную.
- Установи зависимости из requirements.txt через install script egg.

## 2. Только три настройки

В Pterodactyl Startup / Variables:

| Переменная | Значение |
|---|---|
| PROCESSOR_IP | 0.0.0.0 |
| PROCESSOR_PORT | порт allocation, например 9443 |
| PROCESSOR_SECRET | случайный общий секрет |

Сгенерируй секрет:

\`\`\`bash
openssl rand -hex 32
\`\`\`

Скопируй его в безопасное место. Он должен совпадать на обеих сторонах. Не вставляй его в GitHub или публичные логи.

PROCESSOR_IP=0.0.0.0 — это адрес прослушивания внутри Pterodactyl, не публичный IP. Боты подключаются к публичному IP, назначенному allocation.

## 3. Запуск

Startup command:

\`\`\`bash
python server.py
\`\`\`

Ожидаемая строка в консоли:

\`\`\`text
Encrypted voice processor listening on 0.0.0.0:9443
\`\`\`

После подключения появится Authenticated encrypted client connected.

## 4. Настройки на сервере ботов

В основном .env достаточно заполнить три строки:

\`\`\`dotenv
AUDIO_PROCESSOR_IP=203.0.113.10
AUDIO_PROCESSOR_PORT=9443
AUDIO_PROCESSOR_SECRET=ТОТ_ЖЕ_СЕКРЕТ
\`\`\`

Здесь указывается публичный IP Pterodactyl-сервера, не 0.0.0.0. Удалённая обработка включается автоматически, когда заполнены IP и secret. Если оба значения пустые, остаётся локальный микшер. Если удалённый процессор недоступен, клиент автоматически использует локальный fallback и повторяет подключение.

## Протокол и ограничения

- Взаимная аутентификация по общему секрету с HMAC-SHA256.
- AES-256-GCM для конфиденциальности и целостности каждого TCP record; ключи и nonce-prefix выводятся для каждой сессии через HKDF-SHA256 и случайные handshake nonce.
- Сертификаты и приватные ключи не требуются.
- Bus 0: Discord → Lolka; bus 1: Lolka → Discord.
- PCM 48 kHz, stereo, signed 16-bit, кадры по 20 ms.
- Не более шести активных говорящих; до четырёх кадров в очереди на говорящего.
- При переполнении удаляются старые кадры, чтобы не накапливать задержку.
- Аудио не сохраняется на диск.

Открывай TCP-порт только для IP сервера с ботами, если он статический. Общий секрет должен быть случайным и уникальным. Шифрование защищает содержимое даже при подключении через публичный интернет, но фильтрация источника в firewall дополнительно уменьшает поверхность атаки.

Задержка зависит от сетевого RTT между серверами. Проверь звук на живых каналах.
